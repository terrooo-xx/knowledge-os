# 阶段⑩.5：Control Center 启动体验优化

> 只改善启动方式：从"手动 PowerShell + python 命令 + 手动开浏览器"变为"桌面双击即用"。
> 不修改 Knowledge OS 核心架构、不重写 server.py、不新增服务。

## 1. 当前问题

每次使用 Control Center 需要：打开 PowerShell → `cd` 项目根 → `python 90_System/control_center/server.py` → 手动打开浏览器。

## 2. 目标

```text
桌面双击「Knowledge OS Control Center」
  → 自动启动/检测 localhost:8765
  → 自动打开默认浏览器
```

## 3. 启动器设计

- `start_control_center.bat`：一键启动器（GBK 编码 + CRLF，适配中文 Windows cmd）。
- 流程：① 自身位置反推项目根（不硬编码）→ ② curl 探测 `/api/health` 判断是否已在运行 → ③ 已在运行则直接开浏览器（情况 B）→ ④ 未运行则选 python/py → ⑤ 独立启动 server（`start /min cmd /c`，工作目录切到项目根）→ ⑥ curl 轮询最多 15 秒 → ⑦ 成功开浏览器 / 失败弹提示并写日志。
- `create_desktop_shortcut.bat`：一次性创建桌面快捷方式（WScript.Shell COM，原生，无第三方依赖）。

## 4. 文件结构

```text
90_System/control_center/
├── server.py / service.py / static/ / activity_log.jsonl   （原有，未改动）
├── start_control_center.bat       （新增，一键启动器）
├── create_desktop_shortcut.bat    （新增，建桌面快捷方式）
└── launcher.log                   （运行日志，gitignored）
```

## 5. Python 环境处理

- 不硬编码解释器路径；优先 PATH 中的 `python`，其次 `py`（`where python` / `where py`）。
- 不创建虚拟环境、不安装新依赖。

## 6. 项目路径处理

- 启动器通过 `%~dp0` + `..\..` 反推项目根（`<root>\90_System\control_center\` → `<root>`）。
- 已验证启动器源码**无任何 `D:\KnowledgeBase` / `C:\` 硬编码**；Vault 整体移动后仍可用。
- 启动 server 前显式 `pushd "%VAULT_ROOT%"`，不依赖双击时的当前目录。

## 7. 服务检测机制

- 用 `curl.exe --max-time 2 http://localhost:8765/api/health` 探测（快速、可靠，Win10+ 自带）。
- 每 1 秒一次、最多 15 秒轮询，直到 HTTP 可达；不用固定 sleep 猜时间。

## 8. 浏览器自动打开

- 用 `rundll32 url.dll,FileProtocolHandler http://localhost:8765` 打开**系统默认浏览器**（不强制 Edge/Chrome）。
- 验证：该命令在本环境不挂起且正常返回；真实桌面同样使用默认浏览器打开。

## 9. 重复启动处理

- 情况 B（已在运行）：先探测 `/api/health`，200 则只 `rundll32` 开浏览器、直接退出，**不启动第二个 server**。
- 已实测：重复运行启动器后 python 进程数不变（1 个），无 `Address already in use`。

## 10. 桌面快捷方式

- `create_desktop_shortcut.bat` 用 PowerShell `WScript.Shell` 在桌面创建 `Knowledge OS Control Center.lnk`，目标指向启动器、工作目录为项目根、使用系统默认图标（不引入第三方/不制作 ico）。
- 逻辑已用临时目录验证（TargetPath/WorkingDirectory/Description 正确）；真实桌面写入在本沙箱环境被权限边界拦截，需用户在真实桌面运行一次即可完成创建。

## 11. 启动失败处理

- 失败时弹出明确提示（未找到 Python / server.py 缺失 / 15 秒不可达），并写入 `launcher.log`（时间、Python 路径、项目根、检测结果、失败原因）。
- 不删除任何文件。

## 12. 测试结果

- 情况 A（冷启动）：服务在约 3.3 秒内被拉起并响应 `/api/health` 200；server 输出重定向进 launcher.log 生效。
- 情况 B（已运行）：启动器快速退出，不启动第二个服务（python 进程数不变）。
- 无硬编码路径（源码扫描确认）。
- 说明：本沙箱为非交互会话，`start` 命令自身不返回属环境限制；真实交互桌面 `start` 立即返回，完整流程正常。

## 17. 已知限制

- 服务由一个最小化控制台窗口常驻（`cmd /c` 持有 python server）；关闭该窗口即停止服务。
- `launcher.log` 混合编码（.bat 的 GBK echo + python 的 UTF-8 输出），仅作排查用，不影响功能。
- 桌面快捷方式的真实创建需在用户桌面运行一次（沙箱无法写 Desktop）。
- 未做开机自启 / Stop 按钮 / 托盘图标（按任务范围不做）。
